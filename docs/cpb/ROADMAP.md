# tp-browser 路線圖

> 基準：本地提交 `f885545`，2026-10-31。本文件是工程建議，不是 BOB 已核定的時程或功能承諾；本次只新增文件。

## 排序與估算原則

以下 **10 項依使用價值排序**：先防止意外使用既有登入資料及人機互相操作，再建立可信驗收、修復核心能力，最後改善維運及量測。價值排名不等於必須完全串行；例如各修復的最小重現測試應隨修復一起完成。

工作量採一位熟悉 Node.js／CDP 工程師的有效人日，包含實作、局部測試與直接相關文件；不含等待 BOB 決策、測試機準備、人工登入或第三方網站驗證。風險指變更與交付不確定性，不是弱點嚴重程度。合計約 **36–58 人日**，並非交付日期。

| 順位 | 下一步與價值 | 估計工作量 | 風險／相依 |
|---|---|---|---|
| 1 | 明確化設定檔匯入與登入狀態保存政策，避免首次使用就接觸日常瀏覽器資料 | 5–8 人日 | 高：涉及既有登入流程、瀏覽器加密及資料遷移；需 BOB 決定預設政策 |
| 2 | 讓人類接手真正阻擋代理寫入，建立可驗證的共駕控制權 | 4–7 人日 | 高：跨 RPC、頁內 UI 與並行請求；需界定交接中的動作處理 |
| 3 | 建立隔離、可重現、會正確失敗的本機驗收入口 | 4–6 人日 | 中：跨作業系統、瀏覽器啟動及暫存資源管理 |
| 4 | 修復上傳與頁面 fetch 的端到端契約，恢復主要工作流程 | 3–5 人日 | 中：DOM 節點、跨來源限制與檔案副作用；依第 3 項測試基礎整合 |
| 5 | 將啟停限制到明確實例並正確保存狀態，避免誤停及殘留 | 4–7 人日 | 高：Unix、Windows、WSL、設定檔鎖及行程生命週期 |
| 6 | 統一 daemon 入口、版本及安裝產物，消除同名不同效 | 3–5 人日 | 中：需保留既有 `ego-*` 相容命令；與第 5 項協調 |
| 7 | 修正 TaskSpace 帳本、關頁及重新載入語意 | 3–5 人日 | 中：影響舊腳本，需相容與復原策略 |
| 8 | 補齊事件訂閱與重連生命週期，提高長批次穩定性 | 4–6 人日 | 中：事件競態、重複動作及中斷時資源清理 |
| 9 | 提升 DOM 觀測與選擇器可信度，明確區分支援範圍 | 4–6 人日 | 中：頁面差異大，不能直接套用完整 Playwright 語意 |
| 10 | 建立可重跑的效能與輸出量基準，讓優化有可比證據 | 2–3 人日 | 低：主要是量測設計；需第 3 項穩定環境 |

## 各項範圍與完成條件

### 1. 設定檔與登入狀態政策

**依據：** [profile-init.js](../../tools/profile-init.js) 會自動選擇來源並複製登入相關資料；[page-ops.js](../../daemon/page-ops.js) 的 vault 會備存 Cookie、HTTPS 網頁儲存，並把工作階段 Cookie 延長約三十天。

建議新安裝預設空白設定檔；來源匯入、持久化及保存期限分別明示選用。既有資料先提供只含分類及數量的預覽，不自動移除或覆寫；不能把調整目的目錄的環境變數當成禁止讀取來源的開關。補齊刪除同步、等長值更新與錯誤回報。

**完成條件：** 在沒有選用匯入的測試環境不讀取日常瀏覽器資料；以合成測試資料驗證啟停、刪除、期限及等長更新；停用備存後不產生額外登入資料副本。不得以真實帳號資料作公開測試附件。

### 2. 共駕控制權

**依據：** daemon 的共駕回呼引用不存在的 `Store.findByTargetId()`；`space.handOff` 只改狀態，`space.waitForControl` 立即回傳，`pageCall()` 沒有 ownership 閘。

以同一個狀態機管理 UI 與 RPC。保守方案是在交接期間拒絕新的變更操作、明確告知已有動作是否完成；不要自動重送點擊、送出或其他可能重複生效的操作。

**完成條件：** 人類接手後導覽、輸入、上傳與任意執行入口依政策被阻擋；等待控制權真正等待且可逾時；切回代理後才恢復。兩個客戶端並行及分頁關閉時不得出現雙重控制權。

### 3. 可重現本機驗收

**依據：** [package.json](../../package.json) 沒有測試指令；[smoke.ego.js](../../tests/smoke.ego.js) 有固定 `/tmp` 路徑及 23 個檢查，部分斷言失敗仍以零碼結束；Unix 安裝產物缺少完整測試素材。

優先使用 Node.js 內建測試能力；明確分開不連線的單元／契約測試及需瀏覽器的整合測試。測試行程使用專用資料根、臨時輸出目錄、本機合成頁及明確 PID，不呼叫可能掃到既有行程的啟停腳本。

**完成條件：** 一個本機命令能回報通過、失敗或環境未備妥；任何斷言失敗退出非零；清理只影響自己的資源；三平台各有實際執行紀錄。加入上傳、fetch、交接及重啟案例，不只重跑原有 23 項。是否整合 CI 另案決定，本次不改工作流程。

### 4. 上傳與 fetch 契約

**依據：** `markForDom()` 產生的 `egoid-…` 與驗證器期待的 `ego-數字` 不符；`fetchIn()` 的雙參數函式與 `evaluate()` 單參數協定不符。`waitForFileChooser()` 對由 `task.page()` 建立、尚未更新 target 的物件也需驗證。

統一標記產生及驗證規則，保留拒絕非法標記的行為；將 fetch 參數改為符合既有單參數傳遞契約。不要藉由移除路徑或節點驗證讓測試假通過。

**完成條件：** 合成頁驗證單檔／多檔、隱藏 file input、無效路徑、選檔事件與實際收到的位元組；同來源 fetch 驗證方法、標頭、狀態、本文及另存內容，跨來源失敗明確回報。

### 5. 啟停及實例隔離

**依據：** [tp-start.sh](../../scripts/tp-start.sh)、[tp-stop.sh](../../scripts/tp-stop.sh) 依名稱／命令列匹配停止行程；Windows 啟動與停止腳本的匹配規則不同。替代通訊埠仍共用資料根，Unix 停止路徑會接觸兩組埠位。

為實例建立可驗證的 PID、執行檔、設定檔及通訊埠對應；先核對歸屬再停止。先確認保存及關閉結果，再處理殘留；禁止只因有鎖檔就判定它過期。保留單實例為預設，是否支援多實例另行決定。

**完成條件：** 放置另一個瀏覽器及 daemon 作對照，啟停只影響指定實例；通訊埠被占用、過期 PID、保存失敗及鎖被使用時正確中止。有頭與無頭互切有明確結果，不以健康端點代替視窗存在驗證。

### 6. 入口及安裝一致性

**依據：** [兩個 daemon](ARCHITECTURE.md) 功能不同；套件、CLI、新分頁版本不同；[install.sh](../../install.sh) 未遞迴複製本文件目錄及完整測試，[install.ps1](../../install.ps1) 未複製部分套件與授權檔案。

將實作收斂到單一來源，別名只做轉接；建立單一版本來源與安裝檔案清單。安裝器提供變更預覽，對相容命令、其他工具的技能目錄、PATH 與自動啟動採明確選擇，不默默覆蓋。

**完成條件：** 來源樹、安裝後命令、兩個相容名稱及服務範本通過同組契約；具有相同路由與復原行為；安裝完整包含模組、測試素材、文件及授權檔。重複安裝不破壞既有資料或其他工具。

### 7. TaskSpace 帳本一致性

**依據：** `closePage()` 實為解除綁定；`reload` 使用未隨導覽更新的 `pg.url`；部分 `finish(keep)` 留有關閉標籤；`Store.persist()` 沒有跨行程互斥。

先定義 release、close、finish、adopt 與重啟的不同語意，再一致更新帳本。對同名空間並行建立、重複 adopt 及部分保留補上衝突處理；名稱相容調整需棄用期。

**完成條件：** 關閉後瀏覽器與帳本一致；重新載入保留目前網址；部分保留只剩有效標籤；daemon 重啟後失效 target 有可預期結果；讀寫失敗不得回報已可靠保存。

### 8. 事件與重連

**依據：** [createClient()](../../lib/sdk.js) 的 SSE 延遲啟動且不重連；[BrowserHub](../../daemon/page-ops.js) 建立週期計時器，但沒有明確的整體銷毀流程；CDP 與事件等待各有生命週期。

提供訂閱就緒訊號，再允許觸發待觀察動作；連線結束時立即以明確錯誤完成等待者，必要時重新訂閱。為 hub、CDP 等待、監聽器及計時器建立統一清理。

**完成條件：** 快速彈窗／下載不因首次訂閱而漏接；daemon 或瀏覽器中斷時不只有模糊逾時；反覆重連不累積計時器。不得自動重播可能產生副作用的 RPC。

### 9. 觀測與選擇器

**依據：** [inpage.agent.js](../../daemon/inpage.agent.js) 是自製 DOM 快照，有 4,000 節點走訪預算、文字截斷及輸入值輸出；沒有完整 iframe／Shadow DOM 遍歷。文字選擇器的提早返回也使後面的部分 `nth` 分支無法生效。

明確定義可見性、參照有效期、截斷及選擇器子集，為截斷輸出增加可判讀標記。預設不輸出敏感輸入值；框架與 Shadow DOM 支援依實際需求分階段處理。

**完成條件：** 用合成頁驗證隱藏／離開視窗元素、重複文字、重新導覽後參照、`hidden`／`detached` 等待及快照截斷；密碼欄測試值不出現在輸出。未支援的選擇器必須明確失敗，而非執行錯誤元素。

### 10. 效能與量測

**依據：** [bench-run.ego.js](../../tests/bench/bench-run.ego.js) 量測十頁快照字元、行數及 PNG 位元組，不直接量測模型 Token、任務成功率或端到端時間；畫布頁內 script 也需先確認可實際執行。

修正並驗證測試素材，記錄提交、Node.js／瀏覽器版本、實際視窗大小、重複次數、耗時分布及成功條件。將觀測資料量與模型成本拆開報告，不把 PNG 位元組直接換算成 Token。

**完成條件：** 同一環境重跑可比較；包含預熱及多次量測；畫布與純 DOM 各有有效案例；只有測得的指標才能進入結論。對外效能宣稱及正式網站基準另經確認，不沿用舊百分比當本版驗收。

## 決策點

| 需要 BOB 決定 | 尚未決定前的保守建議 |
|---|---|
| 是否接受空白設定檔為新安裝預設，以及登入狀態保存期限？ | 不自動匯入、不延長工作階段登入態；既有資料不刪除、不轉換。 |
| 共駕交接時哪些唯讀操作仍可執行？ | 先阻擋新變更操作；無法判定是否唯讀的任意 JS／CDP 不自動放行。 |
| 第一階段平台與瀏覽器驗收範圍？ | 先在專用測試環境建立三平台基線，再依實際使用頻率排實作，不宣稱未測組合可用。 |
| 是否承諾多實例、相容 API 與安裝自動啟動？ | 保持單實例；保留別名、不擴張相容承諾；自動啟動與技能部署改為明示選用的提案。 |
| 是否另開實作與發布／CI 工作？ | 本次僅交付文件，未修改程式、工作流程、憑證或正式服務。 |
