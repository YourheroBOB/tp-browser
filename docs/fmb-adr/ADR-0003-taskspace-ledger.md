# ADR-0003：以 TaskSpace 與頁面標籤管理工作狀態

- **狀態**：現行設計
- **範圍**：工作空間、頁面生命週期與持久化

## 背景

Agent 需要以穩定名稱操作多個頁面，也需要在 daemon 重啟後恢復可重新連結的工作資訊。`daemon/store.js` 將工作空間資料保存為 JSON，包含下一個工作空間 ID、頁面標籤序號、工作空間與頁面對應的 `targetId`。檔案註解說明，瀏覽器仍認得的 target 可重新連結；瀏覽器已不存在的 target 則會被移除。

## 決策

- 以 TaskSpace 作為一組相關頁面的工作單位。
- 在 TaskSpace 內以 `p1`、`p2` 等頁面標籤識別頁面，並將標籤對應到瀏覽器 target。
- 由 Store 保存工作空間帳本；寫入時先嘗試寫入暫存檔再重新命名，失敗時使用直接寫入的 fallback。
- 不把 JSON 帳本視為瀏覽器頁面內容本身；瀏覽器 target 是否仍有效，仍取決於瀏覽器狀態。

## 取捨

- **優點**：工作腳本可用穩定標籤引用頁面；daemon 重啟後具備重新連結所需的記錄。
- **代價**：持久化資料可能與瀏覽器實際狀態不同步，因此恢復時需要檢查 target 是否存在。
- **代價**：JSON 帳本適合簡單狀態管理，但不提供資料庫層級的交易或多程序協調保證。

## 後果

- 修改頁面建立、移除或重新連結流程時，同時檢查 Store 的更新時機與失效 target 清理方式。
- 不要只依賴標籤序號推定頁面仍存在；應以 daemon 與瀏覽器的實際狀態為準。
- 新增持久化欄位時，考慮既有 JSON 的載入相容性與損毀時的復原行為。
- Store 的直接寫入 fallback 不應被描述為完整的原子性保證。
