# ADR-0006：本機服務的安全邊界

- **狀態**：專案文件所述的現行設計；實作細節需以 daemon 原始碼確認
- **範圍**：daemon、CDP 端點與本機資料

## 背景

專案 README 將工具定位為個人電腦或專屬開發工作站使用，並描述 daemon 與 CDP 僅綁定本機迴路、HTTP 請求進行來源與授權檢查，以及檔案路徑與本機資料的存取限制。`bin/tp-browser.js` 會讀取本機 daemon 狀態與授權資料，並在 RPC 請求中附帶授權標頭。

本 ADR 記錄這項安全設計意圖；本次可讀到的 daemon 實作不完整，因此不將 README 的說明等同於本次已驗證的安全保證。

## 決策

- daemon 與瀏覽器 CDP 端點應只供本機使用，不應暴露到區域網路或公開網路。
- 對 daemon 的操作請求應有授權與來源檢查。
- 檔案操作應限制在明確允許的本機路徑範圍。
- 使用者 Profile、登入狀態與授權資料都屬敏感本機資料，不得寫入 repo 文件、測試 fixture 或一般日誌。

## 取捨

- **優點**：本機控制介面不以遠端服務為前提；將使用者瀏覽器資料留在本機。
- **代價**：本機服務仍具備操作瀏覽器與檔案的能力，因此 loopback、授權、來源驗證與路徑限制都是重要安全邊界。
- **代價**：本地化不代表適合多人共用主機；不同 OS 使用者仍需具備各自的隔離環境。

## 後果

- 修改 HTTP 路由、授權或檔案操作時，必須對照 daemon 實作確認安全檢查仍涵蓋新增路徑。
- 測試使用明顯的假值與本機測試資料，不連線正式服務，也不使用真實帳號資料。
- 在沒有檢視完整 daemon 實作與相關測試前，不應宣稱安全屬性已通過本次驗證。
