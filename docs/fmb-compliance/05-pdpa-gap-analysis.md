# 05 — 台灣個人資料保護法一般要求對照與缺口

> 法源：《個人資料保護法》（下稱個資法）。第27條課予非公務機關適當安全措施義務，細目由各中央目的事業主管機關另定，本文不引用未經核對的單一行業辦法案名。本文僅做一般性對照，**不構成法律意見**；最終判斷應由具執業身分的 BOB 覆核。條號只寫條文結構明確者。

## 0. 適用與免責的前提判斷

- 個資法 §51 第 1 項第 1 款排除「自然人為單純個人或家庭活動目的」之蒐集、處理或利用。**消費者用 tp-browser 管理自己的登入態與瀏覽，很可能落入免責範圍**——這是本專案對外定位（消費端工具）下合理的初步判斷。
- 但 BOB 為執業律師：**以本工具處理案件研究、當事人文件、律所行政，即屬專業／事業目的，不應主張免責**，應以非公務機關標準自我要求。此外，律師對當事人資料另負執業倫理上的保密義務（律師法及律師倫理規範），其要求高於個資法一般水準。
- 保守決策：**以「不免責」為預設立場做本矩陣**；對消費端使用者則以「透明揭露＋預設最小化」作為產品責任的對應。

## 1. 缺口矩陣

| 個資法要求 | 條文基礎 | 現況 | 缺口評等 | 說明與建議 |
|---|---|---|---|---|
| 蒐集處理之特定目的、合法要件 | §5、§19 | 未有任何目的宣告 | 🔴 高 | `tools/profile-init.js` 在**無告知、無同意、無預設關閉**的情況下，把使用者主瀏覽器的密碼庫、自動填表、Cookies 連同解密金鑰（os_crypt）複製進 agent profile。建議：(a) 預設**不**複製 Login Data／Web Data／os_crypt，改以明示 flag（如 `--sync-auth`）才開啟；(b) 執行時列印將複製的項目清單並要求確認 |
| 告知義務（間接蒐集之當事人） | §8、§9 | 對次要當事人（頁面內容中的第三人）無任何機制 | 🟡 中 | 工具層無法代履行律師的告知義務，但**文件應明確警示**：經由 `snapshot`／`evaluate` 擷取並送交外部 LLM 的內容若含第三人個資，需由使用者依其自身角色判斷 §8／§19 合法要件 |
| 目的外利用之限制 | §5、§20 | profile-init 把「個人日常瀏覽資料」引入「Agent 自動化處理環境」，屬目的框架的實質擴張 | 🔴 高 | 同上建議 (a)；並考慮以獨立、非複製來源的「乾淨 profile」作為預設，登入態由使用者主動匯入特定站點 |
| 當事人權利（查閱、補充更正、停止處理利用、刪除） | §3 | 無查閱／刪除介面 | 🟡 中（免責情境下低；執業情境下高） | 至少提供：`tp-browser data inventory`（列出資料根目錄下各檔案類別與大小）與 `tp-purge`（見 `03-retention-and-deletion.md` #3） |
| 安全維護措施：存取控制 | §27 | `0700`／`0600`／`icacls` 已落實；loopback 綁定、timingSafeEqual、safePath（README 宣稱；daemon 實作未完整驗證） | 🟢 低（待驗證） | 良好基礎；未驗證項應補動態測試（沿用 security CHECKLIST） |
| 安全維護措施：資料銷毀與紀錄 | §27 | 無 | 🔴 高 | 見 `03-retention-and-deletion.md`；銷毀紀錄可由 `tp-purge` 輸出摘要起步 |
| 安全維護措施：日誌與稽核軌跡之保護 | §27 | 日誌本身含敏感欄位（見 `04-log-leak-fields.md`）且無輪替 | 🔴 高 | 「用來做稽核的檔案本身是最大的外洩源」是本專案特有的矛盾點；優先實作去識別化規則 |
| 傳輸與跨境 | §5、§20、§21 | 工具本身零對外傳輸；但預設工作流把頁面內容送外部 LLM | 🟡 中 | 第21條是中央目的事業主管機關得限制非公務機關國際傳輸的規定，並非不適用私人；跨境傳輸同時是利用行為。在 README／SKILL 加「資料出境」警示：擷取內容送交模型服務＝跨境利用；案件資料未經當事人同意或去識別化前，不應進入外部服務。執業用途建議以本地／自架模型或明確 DPA 的服務為限 |
| 委外處理（LLM 服務商） | §27 | 無任何委外管理文件 | 🟡 中 | 律所層級議題而非工具議題；建議在律所內部合規文件把「Agent 瀏覽器＋外部模型」列為委外項目並留存服務條款/DPA |
| 事故通報與應變 | 現行法對多數私人部門尚無普遍強制通報，屬最佳實務與執業倫理 | 無 | 🟡 中 | 建議最小應變卡：發現 token／cookies 外洩時，立即 `tp-stop`＋`tp-purge`（未來指令）＋變更相關帳號密碼＋評估對當事人之通知 |
| 隱私權政策／透明揭露 | §5 | README 強調「100% 本機自持」但**未揭露** profile-init 會複製主瀏覽器密碼庫與 os_crypt | 🔴 高 | 行銷話術與實際資料行為不一致是最大聲譽風險；README 應增「隱私與資料行為」節：明列會複製哪些檔案、存於何處、如何清除（本輪不改 README，列為建議） |

## 3. 明確不建議做的事（過度工程防線）

- 不建議在工具內建「自動上傳／雲端同步」或任何形式的遙測外傳——這會同時摧毀 Apache-2.0 零相依定位與「本機主權」承諾。
- 不建議為了「合規」而在工具內硬做使用者身分驗證／帳號系統——單機工具以檔案權限為邊界即可，帳號化反而創造新的個資檔案。
- 涉及既有程式修改的建議（P0/P1）均屬另案 PR；本輪僅完成盤點與文件。

## 4. 決策點（本文件自行拍板的保守立場，待 BOB 覆核）

1. 以「執業用途不免責」為矩陣預設立場。
2. 以「預設最小化、機敏複製改 opt-in」為 profile-init 的建議方向（現行實作方向相反，屬需要 BOB 拍板的產品決策，因為它直接影響「登入態無縫」這個核心賣點）。
3. 「本機主權」的行銷宣稱以「工具自身零外傳」為準確表述；使用模式造成的外流以警示文件處理，而非宣稱工具可防堵。
