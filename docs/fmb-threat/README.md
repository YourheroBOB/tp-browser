# tp-browser 威脅模型（STRIDE）— 索引與方法說明

- **文件版本**：v1.0（草案，待審）
- **適用版本**：`package.json` 宣告 `0.3.0`；CLI `version` 子命令輸出 `0.3.1`
- **範圍**：本機端 `tp-browser` / `tp-browserd`（別名 `ego-browser` / `ego-browserd`）之 daemon、CLI、SDK、安裝器、啟動腳本、profile 初始化工具、Agent Skill 檔
- **非範圍**：Chrome/Chromium/Edge 本身之 0-day、Node.js 執行環境本身之漏洞、GitHub 平台安全、使用者所造訪網站之安全
- **與 `docs/fmb-security/` 的關係**：該目錄已描述本專案的既有防線原理與設定方式，**本目錄不重述**。本文僅以代號 `C1`–`C6` 指涉該組既有控制，聚焦於「這些控制的覆蓋邊界之外還剩下什麼」，以及「哪些假設其實沒有被程式碼強制執行」。

## 1. 為什麼還需要這份文件

`docs/fmb-security/` 回答的是「我們做了哪些防護、怎麼設定」。本文件回答三個不同的問題：

1. **攻擊者從哪裡進來**：把「網頁內容」、「同一台機器的其他行程」、「同一台機器的其他 OS 使用者」、「安裝來源」、「LLM 代理」全部視為可能的攻擊者起點，逐一對照目前程式碼能攔到哪一層。
2. **哪些防護其實沒有被程式碼強制**：多項防護是靠**啟動腳本**（`scripts/tp-start.sh`、`scripts/ego-start.ps1`）落實的，而不是靠 daemon 自己。只要有人用 `node daemon/ego-browserd.js` 直接啟動（`tp-browser doctor` 的修復提示就建議這樣做），那層防護就不存在。
3. **優先順序**：哪些缺口應該先補、補完怎麼驗收、補的時候會不會打破既有 Agent 腳本。

## 5. 分析前提（若前提不成立，風險評分需重算）

| 編號 | 前提 | 若不成立 |
|---|---|---|
| `P1` | 部署於**單一使用者**個人電腦或專屬工作站 | 多使用者主機時，多條 Loopback 相關威脅（`I-01`、`S-01`、`D-01`）機率由「中」升為「高」 |
| `P2` | 使用者**不會**刻意把 `~/.local/share/ego-linux` 放進雲端同步資料夾 | `I-08` 由推測變成高風險洩漏路徑 |
| `P3` | 使用者的 LLM 代理會**完全信任** `skills/tp-browser/SKILL.md` 的指示 | 這是本模型的關鍵前提：Skill 檔等同「寫給代理的程式碼」，其完整性要求應比照執行檔 |
| `P4` | 被瀏覽的網頁內容一律視為**不可信輸入** | 目前程式碼沒有任何機制在代理端維持這個假設（見 `E-02`） |
| `P5` | daemon 由啟動腳本拉起（而非直接 `node daemon/...`） | `C6` 的檔案權限會失效（見 `T-01`） |

## 6. 已知限制

1. **五個核心檔案未提供**：`daemon/tp-browserd.js`、`daemon/ego-browserd.js`、`daemon/page-ops.js`、`daemon/inpage.agent.js`、`lib/sdk.js`。因此與 HTTP 路由、認證中介層、路徑檢查、SSE 推送相關的判斷，最高只能到 `[HYP]`，並附驗證方法。
2. **`docs/fmb-security/` 未提供**：本文以代號引用，不臆測其內容；若該目錄日後補上與本文重疊之段落，以該目錄為準，本文僅保留「缺口與驗證」部分。
3. **未執行任何動態測試**：所有 `[CODE]` 級斷言均來自靜態閱讀。`02` 檔各條目附有可執行的驗證指令，但本次未執行（本任務不得連線正式服務、不得讀寫 repo 外路徑）。
4. **未進行定量風險計算**：採「可能性 × 影響」定性分級，理由見 `02` 檔第 1 節。

## 7. 維護方式

- 每當新增一個**對外可觸及的端點**、**新的檔案寫入路徑**、**新的安裝/啟動步驟**、或**新的代理 Skill 指示**，就要對應更新 `01` 的攻擊面入口表與 `02` 的威脅目錄。
- 每結案一個 `M-nn` 修補項目，請在 `04` 對應列標記「已修補（版本）」並保留原驗收測試作為回歸測試。
- 若日後支援多使用者或遠端（非 loopback）存取，`P1` 前提失效，整份文件的風險評分必須重算。

## 8. 文件內資料處理原則（自我約束）

本目錄所有範例一律使用明顯假值，例如 token 範例固定寫 `FAKE_VALUE_FOR_TEST`。文件不記錄任何真實的 Cookie、Session、Token、金鑰、個資或案件內容；驗證指令只輸出狀態碼與欄位名，不輸出內容本體。
